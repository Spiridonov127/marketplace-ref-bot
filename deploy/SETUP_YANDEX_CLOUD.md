# Перенос бота на Yandex Cloud (бесплатный грант)

Идея та же, что в [SETUP_VPS.md](SETUP_VPS.md) — уйти с расшаренных IP GitHub
Actions на "тихий" российский IP, чтобы Яндекс Маркет не показывал капчу.
Разница: вместо платного ВПС используем бесплатный грант Yandex Cloud
(обычно выдаётся новым аккаунтам на 60 дней), а IP при этом принадлежит
самому Яндексу — датацентр `ru-central1`, Москва/Владимир.

**Важная оговорка, честно:** нет гарантии, что IP именно Yandex Cloud не
попадёт под капчу — это тоже датацентровый диапазон, просто "свой" для
Яндекса и российский. Шанс лучше, чем у GitHub Actions, но не 100%. Первый
же реальный запуск покажет: если капча всё равно появится — в логе будет
«Яндекс Маркет показал капчу», скриншот ляжет в `data/ym_debug_captcha.png`.
В этом случае остаётся домашний ПК/Raspberry Pi или платный ВПС у другого
провайдера.

Всё ниже — шаги, которые нужно выполнить вам самим (регистрация аккаунта,
ввод карты для верификации, клики в консоли Yandex Cloud) — их не может
сделать никто за вас удалённо. После получения IP и SSH-доступа дальнейшую
настройку сервера я выполню сам, если дадите доступ, либо вы просто
скопируете команды из раздела 4.

## 1. Регистрация и грант

1. Откройте https://cloud.yandex.ru/ и зарегистрируйтесь (нужен аккаунт
   Яндекса — Почта/Паспорт).
2. При первом входе Yandex Cloud предложит активировать пробный период —
   потребуется привязать банковскую карту для подтверждения личности.
   **Деньги не спишутся**, пока не закончится грант и вы сами явно не
   включите платный режим — но карту в целях безопасности вводите сами,
   я этого сделать не могу и не должен.
3. После активации в личном кабинете (Billing) будет виден грант в рублях
   и дата его окончания — **запомните эту дату**, к ней нужно либо продлить
   (перейти на платный тариф), либо остановить машину, чтобы не было
   сюрпризов после истечения гранта.

## 2. Создать виртуальную машину

В консоли: Compute Cloud → Создать ВМ.

- **Имя**: `marketplace-bot`
- **Зона доступности**: `ru-central1-a` (любая — все российские)
- **Образ**: Ubuntu 24.04 LTS
- **Платформа**: Intel Ice Lake (или дефолтная) — не важно для этой задачи
- **vCPU/RAM**: 2 vCPU (с гарантированной долей 5-20%) / **2 ГБ RAM** —
  этого хватает (Chromium прожорлив, меньше 2 ГБ брать не стоит, см.
  причины в SETUP_VPS.md п.1)
- **Диск**: 20 ГБ, стандартный (HDD/network-hdd) — дешевле, скорость не
  критична
- **SSH-ключ**: в поле "SSH-ключ" вставьте содержимое файла
  `~/.ssh/id_ed25519.pub` с вашего компьютера — это НЕ пароль, а публичный
  ключ, его можно спокойно вставлять куда угодно. Логин по умолчанию —
  `yc-user` (Yandex Cloud создаст его сам под этот ключ).
- Нажмите **Создать ВМ**.

Через минуту в списке ВМ появится **внешний IP-адрес** — он и нужен для
следующих шагов.

## 3. Первый вход

```bash
ssh yc-user@ВАШ_IP
```

(Ключ уже есть на этом компьютере — `~/.ssh/id_ed25519` — ssh подхватит его
автоматически, пароль не спросит.)

## 4. Дальше — как в обычном ВПС

Начиная с этого момента шаги идентичны [SETUP_VPS.md](SETUP_VPS.md), пункты
3–8, с двумя отличиями:

- команды выполняйте с `sudo` (пользователь `yc-user`, не `root`):

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install -y python3 python3-venv python3-pip git

cd ~
git clone https://github.com/Spiridonov127/marketplace-ref-bot.git
cd marketplace-ref-bot

python3 -m venv venv
./venv/bin/pip install --upgrade pip
./venv/bin/pip install -r requirements.txt playwright
./venv/bin/playwright install --with-deps chromium
```

- путь для `.env` и куки — `/home/yc-user/marketplace-ref-bot/` вместо
  `/root/marketplace-ref-bot/`:

```bash
# на своём компьютере, в отдельном терминале
cd ~/marketplace-ref-bot
scp .env yc-user@ВАШ_IP:~/marketplace-ref-bot/.env
scp data/dzen_cookies.json data/distribution_cookies.json \
    yc-user@ВАШ_IP:~/marketplace-ref-bot/data/
```

Отключить вебхук Telegram (обязательно, иначе конфликт с Cloudflare
Worker), пробный ручной запуск, автозапуск через systemd — см.
SETUP_VPS.md пункты 6-8, команды те же самые, только путь
`/root/marketplace-ref-bot` меняйте на `/home/yc-user/marketplace-ref-bot`
(включая `marketplace-bot.service`, если копируете его — поправьте
`User=`/`WorkingDirectory=` внутри на `yc-user`/новый путь).

## 5. Проверка на капчу — не пропускайте этот шаг

После первого реального запуска (`/start` из Telegram → категория) —
обязательно проверьте `data/ym_debug_captcha.png` на сервере:

```bash
ls -la ~/marketplace-ref-bot/data/ym_debug_captcha.png 2>/dev/null && \
  echo "КАПЧА БЫЛА — этот IP тоже не подходит" || \
  echo "Капчи нет — IP Yandex Cloud подошёл"
```

## 6. Капча на Yandex Cloud IP тоже есть — обязательный туннель

Подтверждено на бою: Яндекс Маркет капчит **любой датацентровый IP**,
включая сам Yandex Cloud — не помогает то, что это российская
инфраструктура самого Яндекса. Капчатся по типу IP (хостинг/датацентр), а
не по стране. Поэтому только трафик к market.yandex.ru отдельно заворачивается
через обратный SSH-туннель до домашнего компьютера — Telegram и Дзен это
не затрагивает, они у капчи не замечены.

**На домашнем компьютере** (том, что реально подключён к обычному
интернету, не ВПС):

```bash
cp deploy/ym-proxy-tunnel.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now ym-proxy-tunnel
loginctl enable-linger $USER   # чтобы туннель жил даже без активной сессии
```

Это поднимает SOCKS5-прокси на `127.0.0.1:1080` **на ВМ**, но трафик через
него реально выходит в интернет с вашего домашнего IP.

**На ВМ** — в `.env` добавить:

```
YM_PROXY_URL=socks5://127.0.0.1:1080
```

и перезапустить бота (`sudo systemctl restart marketplace-bot`).

Важное следствие: домашний компьютер теперь должен быть включён и в сети,
иначе парсинг Яндекс Маркета не будет работать (хотя Telegram и Дзен
продолжат работать с ВМ независимо). Если планируете надолго выключать
компьютер — правильнее вернуться к варианту "всё на домашнем ПК" целиком.

## Если грант закончился или капча всё же есть

- Грант закончился → либо переводите биллинг-аккаунт на платный режим
  (это уже не бесплатно), либо останавливаете ВМ (Stop) — данные и диск
  сохранятся, деньги не списываются за выключенную ВМ, кроме диска
  (копейки).
- Капча есть → возвращаемся к варианту "домашний ПК/Raspberry Pi" — там
  IP точно "тихий" и жилой, см. обсуждение в чате.
